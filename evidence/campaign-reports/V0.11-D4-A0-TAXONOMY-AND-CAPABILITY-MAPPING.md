## 1. 新主线定义

> **Compression Opportunity Taxonomy & Capability Coverage Benchmark**
> ——面向真实 Agent trajectories，建立压缩机会分类体系，量化 TASCO
> 现有能力对公开任务集的覆盖范围、可压缩规模、风险边界与能力缺口。

研究问题（论文口径）：

```text
RQ1 自然 coding-agent trajectory 中有哪些压缩机会？
RQ2 这些机会的频率、大小、重复度、后续消费风险如何？
RQ3 现有压缩 primitives 能覆盖其中多少？
RQ4 哪些自然区域无法通过机械无损压缩处理？
RQ5 离线可压缩性与真实 task-level token saving 为什么会出现差异？
```

D3-E1～E7 已支撑 RQ1/RQ4/RQ5 的核心内容（E13 大输出≠可压缩输出；
高重复≠在线可测收益；mechanism signal ≪ trajectory variance）。

## 2. 五类分类（非二分；负区同发布）

```text
A Existing-capability compressible   现有/冻结候选 primitive 可机械安全处理
B Compressible but unsupported       有机会但需新 semantic primitive
C Opportunity exists but unsafe      内容可缩但下游高度依赖原始信息
D Low-value opportunity              可压但量太小不值得处理
E No meaningful opportunity          无足够重复/冗余/可折叠结构
```

诚实性价值：不仅测量 TASCO 覆盖什么，也**量化其不能覆盖、不应
覆盖的区域**。

## 4. 三层映射结构

```text
第一层 Dataset → Opportunity Shapes（D3-E1 已完成：15K census）
第二层 Shape → TASCO Capability（本次冻结：registry mapping matrix）
第三层 Capability → Dataset-level Coverage（external validation 时计算：
     COC = covered safe-compressible bytes / all identified
     safe-compressible bytes
     SOC = sessions with ≥1 supported opportunity / sessions with
     ≥1 qualified opportunity
     Capability Gap = natural opportunity but no current safe primitive）
```

方法论边界（论文必须明确）：**Task benchmark evaluates task
correctness；Trajectory benchmark evaluates compression opportunity**。
